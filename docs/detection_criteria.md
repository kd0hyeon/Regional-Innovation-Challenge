## 0. 한눈에 보기

**이 도구는 "악성이다/아니다"를 확정하지 않습니다. 설치 전에 확인 가능한 신호를 점수화해 위험도(통과/경고/부적합)를 판정합니다.**

다음 두 경우는 점수와 무관한 예외 처리입니다. PyPI 미존재는 악성 또는 AI 환각의 확정 증거가 아니며, MAL 리포트도 적용 대상 패키지·버전과 철회 여부를 확인해야 합니다.

| 점수와 무관한 예외 처리 신호 | 처리 |
|---|---|
| PyPI에 존재하지 않는 패키지 | `NOT_FOUND` (AI 환각 슬롭스쿼팅 의심) — 이후 검사 중단 |
| OSV에 악성 패키지 리포트(`MAL-*`)가 있음 (패키지 자신 또는 직접 의존성) | 점수와 무관하게 즉시 `FAIL`(부적합) |

그 외에는 **3개 신호를 합산한 총점(최대 13점)**으로 판정합니다.

| 신호 | 점수 범위 | 위험하다고 보는 이유 |
|---|---|---|
| ① 최초 등록일(등록 후 경과 기간) | 0~5 | 공격자는 AI가 환각한 이름을 선점해 **갓 등록**하는 경우가 많다 |
| ② 주간 다운로드 수 | 1~5 | 낮은 사용량을 보조 신호로 사용한다. 정상 신규·틈새 패키지도 사용량이 적을 수 있다 |
| ③ 인기 패키지와 이름 유사도 | 0~3 | 유명 패키지 이름을 흉내 낸 **타이포스쿼팅** |

**이 3개 신호를 합산한 것만 통과/경고/부적합 총점(최대 13점)에 들어갑니다.**

| 별도 축 (총점에 포함되지 않음) | 표시 방식 | 위험하다고 보는 이유 |
|---|---|---|
| ④ OSV 알려진 취약점(패키지+직접 의존성), **CVSS 공식 심각도 등급** | `security.max_known_severity`와 심각도 미확인·조회 상태를 별도 표시 | 환각/사칭이 아니어도 설치 전 알아야 할 **보안 문제**. 슬롭스쿼팅과는 별개 성격이라 총점에서 분리(v0.7) |

**슬롭스쿼팅 총점 → 판정:** 0~3점 통과 · 4~6점 경고 · 7점 이상 부적합 (최대 13점)

> ⚠️ **통과 ≠ 안전 보증, 부적합 ≠ 악성 확정** 입니다. (예외: `MAL-*` 리포트는 이미 악성으로 보고된 패키지)

> 결과에는 항상 판정 근거(`signals`)가 함께 출력됩니다.

## 1. 판정 결과 6종

| 결과 | 표시 | 종료 코드 | 언제 나오는가 |
|---|---|---|---|
| `PASS` | 통과 | 0 | 총점 3점 이하이고, MAL 리포트와 필수 조회의 누락·실패가 없음 |
| `WARN` | 경고 | 1 | 총점 4~6점 |
| `FAIL` | 부적합 | 2 | 총점 7점 이상, **또는** OSV `MAL-*` 리포트 존재 |
| `NOT_FOUND` | 존재하지 않음(환각 패키지 의심) | 3 | PyPI에 패키지(또는 지정한 버전)가 없음 |
| `UNKNOWN` | 판정 불가(일부 조회 실패) | 4 | 점수상 통과 수준이지만 일부 조회에 실패해 **확신할 수 없음** |
| `INVALID` | 잘못된 입력 | 5 | 지원 입력 형식(`패키지명` 또는 `패키지명==버전`)이나 검증 조건에 맞지 않음 |

여러 패키지를 한 번에 검사하면(`scan`) 종료 코드는 **가장 큰 값**으로 집계하는 설계입니다. 이는 오류 종류의 코드 규칙이며 위험도 순위가 아닙니다. 개별 패키지의 판정은 모두 별도로 출력합니다.

---

## 2. 판정 흐름

| 순서 | 처리 | 결과·예외 |
|---|---|---|
| 0 | 입력 검증 | 형식 오류 → `INVALID` |
| 1 | PyPI에서 패키지와 지정 버전 확인 | 없음 → `NOT_FOUND`, 조회 실패 → `UNKNOWN`; 이후 검사 중단 |
| 2 | 등록 후 경과 기간 계산 | 등록일 점수 0~5 |
| 3 | 최근 1주 다운로드 조회 | 다운로드 점수 1~5; 통계 없음·조회 실패는 §3.3과 §3.7 적용 |
| 4 | 인기 패키지와 이름 비교 | 이름 유사도 점수 0~3 |
| 5 | 패키지 및 직접 의존성의 OSV 조회 | 적용되는 MAL 리포트, 별도 보안 심각도, 조회 상태 수집; 총점에는 미포함 |
| 6 | 점수 합산 | 등록일 + 다운로드 + 이름 유사도 = 최대 13점 |
| 7 | 최종 판정 | MAL → `FAIL`; 그 외 ≥7 → `FAIL`, 4~6 → `WARN`, ≤3 → `PASS` |
| 8 | 검사 완전성 확인 | `PASS` 예정인데 필수 조회 누락·실패가 있으면 `UNKNOWN` |

- MAL 예외는 조회 실패에 따른 `UNKNOWN` 전환보다 우선합니다.
- 이미 `WARN` 또는 `FAIL`이면 일부 조회 실패가 있어도 판정을 유지하고 `incomplete`에 기록합니다.
- 일반 CVE의 CVSS 등급은 총점과 판정에 더하지 않습니다. OSV 실패가 `UNKNOWN`에 영향을 주는 이유는 MAL 확인이 불완전해지기 때문입니다.

## 3. 신호별 상세 기준

### 3.0 입력 검증

- 패키지명: `^[A-Za-z0-9]([A-Za-z0-9._-]*[A-Za-z0-9])?$`, 최대 100자

- 버전: `^[A-Za-z0-9][A-Za-z0-9._+!-]*$`, 최대 64자. 이 정규식은 허용 문자 검사이며 유효한 버전인지 완전히 판별하지는 못하므로 PEP 440 버전 파서로 추가 검증합니다. 전체 PEP 508 문법을 모두 지원한다는 뜻은 아닙니다.

- 형식에 맞지 않으면(예: `../etc/passwd`, `req; rm -rf /`, URL) API 호출이나 외부 명령으로 넘기지 않고 `INVALID` 처리.

- 검사 대상 패키지를 **설치·실행·import 하지 않습니다.** 메타데이터 조회와 문자열 파싱만 합니다.

### 3.1 PyPI 존재 여부

- PyPI JSON API에 패키지명을 조회. 응답이 404이면 `NOT_FOUND`.

- `flask==9.9.9` 처럼 **버전을 지정했는데 그 버전이 없어도** `NOT_FOUND`.

- **존재한다고 안전/악성을 판정하지 않습니다.** 존재 여부는 다음 단계로 넘어갈지만 결정합니다.

- 의미: AI가 만들어 낸 이름이면 PyPI에 없을 가능성이 높다. 단, **이미 공격자가 선점해 등록해 둔 이름은 "존재"** 하므로 등록일·다운로드·이름 유사도 및 MAL 리포트로 위험을 확인한다. 이 신호만으로 모든 선점 공격을 탐지할 수 있는 것은 아니다.

### 3.2 최초 등록일 (등록 후 경과 기간)

- 모든 릴리즈 파일의 업로드 시각 중 **가장 오래된 시각**을 최초 등록일의 추정값으로 사용. 삭제된 과거 파일은 조회되지 않을 수 있으므로 실제 최초 등록일과 다를 수 있음. `현재 − 최초 등록일`을 일(day) 단위(소수 포함)로 계산.

| 등록 후 경과 기간 | 점수 |
|---|---|
| 7일 이하 | 5 |
| 7일 초과~30일 이하 | 4 |
| 30일 초과~90일 이하 | 2 |
| 90일 초과 | 0 |
| 릴리즈 이력을 확인할 수 없음 | 5 (보수적 대체값) + `incomplete` 기록 |

**근거 (실제 제품·공식 문서 기반, v0.6에서 재검토):**

패키지 "등록일" 자체를 다룬 학술 연구는 찾지 못했지만, "새로 게시된 것일수록 위험하다"는 동일한 원리를 쓰는 **쿨다운 정책과 다른 도구의 등록일 구간을 참고**해 7/30/90일을 잠정 채택했습니다. 각각의 자료가 세 구간 모두를 검증한 것은 아니며, 5/4/2/0점은 자체 휴리스틱입니다.

| 구간 | 근거 |
|---|---|
| **24시간** | pnpm 11(2026)은 Minimum Release Age를 기본값 1,440분(24시간)으로 설정해 갓 게시된 버전을 자동으로 차단합니다. |
| **7일** | OpenSSF(2026) 공식 블로그는 "대부분의 오픈소스 악성 패키지는 게시 후 3일 이내에 OSV.dev에 분류된다"고 밝히고, 7일 단위 쿨다운(`min-release-age=7`) 설정을 권장 사례로 제시합니다. Harness의 상세 일수는 원문 재확인이 필요하므로 확정 근거로 사용하지 않습니다. |
| **30일** | `safeinstall`이 <7일/<30일/<90일의 등록일 구간을 사용합니다. 이는 실무 선례이며 30일이 최적 경계라는 통계적 증거는 아닙니다. |
| **90일** | `safeinstall`의 위험 점수 체계는 7일/30일에 이어 90일을 세 번째 구간 경계로 둡니다. |

→ v0.5까지 있던 180일 구간은 이를 뒷받침하는 1차 자료를 찾지 못해 **v0.6에서 제거**했습니다(90일 초과는 모두 0점으로 단순화). 다만 npm/pnpm 쿨다운은 **버전 게시 후 경과 시간**을 다루고, `safeinstall`의 Package age는 패키지 생성 시점을 다룹니다. 근거의 대상이 서로 다르며, 슬롭스쿼팅처럼 **패키지 자체가 새로 등록**되는 경우에 그대로 적용 가능한지는 검증되지 않았습니다. 이 차이는 §8(한계)에 명시했습니다.

- 최근 등록일 **자체를 악성으로 보지 않고**, 위험도 점수의 한 요소로만 반영합니다.

### 3.3 주간 다운로드 수

- pypistats.org의 최근 1주 다운로드 수를 사용합니다. 통계 없음(404)은 실측 0회와 구분합니다. 이때 계산용 대체값 0회(5점)를 사용하되 `signals`와 `incomplete`에 통계 누락을 기록합니다. 네트워크·서버 오류의 대체값은 3점입니다.

| 주간 다운로드 | 점수 |
|---|---|
| 0~349 | 5 |
| 350~14,999 | 3 |
| 15,000 이상 | 1 |
| 통계 없음(404) | 5(계산용 대체값 0회), `incomplete` 기록 |
| 조회 실패 | 3(임시 대체점수), `incomplete` 기록 |

**근거 (v0.6에서 실측 데이터 기반으로 전면 재검토):**

기존 기준(100/1,000)은 근거 없이 다른 도구를 참고만 한 값이었습니다. v0.6에서는 ① **PyPI 다운로드 수의 실제 분포를 다룬 학술 연구**와 ② **실제 악성/타이포스쿼팅 패키지가 적발 당시 기록한 다운로드 수** 두 가지를 직접 찾아 아래처럼 구간을 다시 잡았습니다.

**① 350의 근거 — 과거 데이터에서 참고한 노이즈 기준**

Taylor 외, **SpellBound: Defending Against Package Typosquatting** (arXiv:2003.03471)에 따르면, npm 측 자체 추정으로 **패키지 하나가 실제 설치 없이도 미러·봇에 의해 하루 최대 약 50회, 주 약 350회까지 다운로드될 수 있습니다.** 이는 과거의 봇·미러 트래픽 추정에 기반한 경계이며, 현재 PyPI에서 실제 채택 여부를 확정하는 기준은 아닙니다. 같은 논문은 이 350회 기준을 밑도는 패키지가 **PyPI 전체의 93.3%**에 달한다고 실측했습니다(2020년 2월 스냅샷, PyPI 약 22만 개 패키지 대상).

**② 15,000의 근거 — 선행 연구의 인기 기준**

같은 SpellBound 논문은 npm·PyPI 전체의 다운로드 분포를 데이터 기반으로 분석해, **"확실히 인기 있는 패키지"를 가르는 실용적 기준으로 주간 15,000회를 직접 채택**했습니다(이 기준을 넘는 패키지는 PyPI 전체의 약 3%). 논문은 참고로 주 100,000회 이상(PyPI 상위 0.4%)을 "의심의 여지 없이 인기 있음"의 상한으로도 제시합니다.

**③ 실제 악성/슬롭스쿼팅 유사 사례의 다운로드 수 (적발 시점 기준)**

| 사례 | 적발 당시 다운로드 수 | 출처 |
|---|---|---|
| `pymafka` (PyKafka 타이포스쿼팅, 2022) | 325회 | Yasar, arXiv:2412.05259 인용 |
| `aws-login0tool` (트로이목마, 2023) | 약 600~3,042회 | PortSwigger Daily Swig / BleepingComputer |
| `dpp-client` (2021~2022) | 10,000회+ (최근 1개월만 600회+) | PortSwigger Daily Swig |
| 클라우드 토큰 탈취 캠페인 20종 (2025) | 개별 100~5,496회, 합계 14,100회+ | The Hacker News |
| 정보 탈취형 160종 (Cyble, 2025) | 개별 252~4,000회+, 합계 45,000회+ | Cyble Research |

**이 사례들이 알려주는 것:** 다운로드 수가 수천~수만 회인 악성 패키지도 있습니다. 다만 위 사례의 누적 다운로드나 월간 다운로드를 우리 모델의 **주간 다운로드**와 직접 비교할 수는 없습니다. 이 사례들은 다운로드가 많다고 안전하지 않다는 보강 자료이며, 350/15,000 경계나 5/3/1점을 검증하는 데이터는 아닙니다.

pypistats는 알려진 PyPI 미러를 기본 집계에서 제외합니다(§11 [23]). 따라서 SpellBound의 과거 봇·미러 추정치를 현재 pypistats의 350회와 동일한 노이즈 하한으로 간주하지 않습니다. 두 경계값은 최신 데이터로 재검증할 잠정값입니다.

### 3.4 인기 패키지와 이름 유사도 (타이포스쿼팅)

- 비교 대상: 내장 인기 패키지 목록 175개 (`popular.py`). `--popular-file` 로 자체 목록 지정 가능.

- 방법: 구분자(`-`, `_`, `.`)를 제거한 이름끼리 **Damerau-Levenshtein 편집거리**(삽입·삭제·치환·인접 문자 전치) 계산. 가장 가까운 인기 패키지를 선택.

  - 예: `reqeusts`→`requests` = 1(전치), `numpyy`→`numpy` = 1(삽입), `req-uests`→`requests` = 0(구분자 변형)

- 동일 패키지 면제는 PyPI/PEP 503 정규화(소문자화 후 연속된 `-`, `_`, `.`를 `-`로 치환) 기준으로만 적용합니다. 구분자를 완전히 제거한 비교용 이름은 동일 패키지 판단에 사용하지 않습니다. 따라서 `Requests`와 `requests`는 같은 패키지지만 `req-uests`와 `requests`는 별개입니다.

| 조건 | 점수 |
|---|---|
| PEP 503 정규화로 동일한 패키지 | 0 |
| 다른 패키지이고 편집거리 0~1 (검사 대상의 구분자 제거 후 길이 5자 이상) | 3 |
| 다른 패키지이고 편집거리 2 (검사 대상의 구분자 제거 후 길이 8자 이상) | 2 |
| 그 외 | 0 |

**근거와 적용 범위:** 편집거리와 인기 패키지 비교는 타이포스쿼팅 선행 연구에서 사용하는 접근입니다(§11 [7], [15], [16]). Neupane 외의 연구는 거리 2까지의 후보 탐색을 참고하는 자료입니다. 하지만 해당 연구가 veriPI의 3점/2점, 길이 5자/8자, 내장 목록 175개를 검증한 것은 아닙니다.

Tschacher는 학사논문, KU 자료는 석사논문이며 동료 심사 학술대회 논문과 구분합니다. 무관한 단어도 편집거리가 가까울 수 있다는 오탐 문제를 참고하되, **5자/8자 컷오프는 자체 휴리스틱**으로 명시합니다. `laughter`/`daughter`는 무관한 단어의 유사성 예시이지 5자 미만 이름의 근거는 아닙니다.

주간 다운로드 10만 이상이면 이름 유사도를 무시한다는 원문 문장은 점수표와 충돌하여 삭제했습니다. 이 명세에서는 **다운로드 수에 따른 이름 유사도 면제 규칙을 적용하지 않습니다.**

### 3.5 OSV 알려진 취약점 — 별도 보안 축

OSV API에 `패키지명 + 버전`과 `PyPI` 생태계로 조회합니다. 버전을 지정하지 않으면 PyPI에서 확인한 최신 버전을 사용합니다.

**(a) MAL 리포트**

검사 대상 패키지 또는 직접 의존성의 검사 버전에 적용되는, 철회되지 않은 `MAL-*` 리포트가 있으면 총점과 무관하게 `FAIL`입니다. 이는 알려진 악성 보고에 따른 예외 판정이지, 슬롭스쿼팅 공격 경로 자체를 확정하는 것은 아닙니다. MAL은 일반 취약점의 CVSS 집계에서 제외하고 `signals`에 리포트 ID·대상·버전을 기록합니다.

**(b) 일반 취약점의 심각도**

CVSS는 FIRST가 관리하는 취약점 심각도 평가 체계입니다. 아래는 CVSS v3.x의 공식 정성 등급이며, 공격 발생 확률이나 슬롭스쿼팅 가능성을 나타내지는 않습니다(§11 [22]).

| CVSS 점수 | 등급 |
|---|---|
| 0.0 | NONE |
| 0.1~3.9 | LOW |
| 4.0~6.9 | MEDIUM |
| 7.0~8.9 | HIGH |
| 9.0~10.0 | CRITICAL |

- OSV의 해당 패키지 `affected[].severity`와 최상위 `severity`를 확인합니다. 패키지별 정보가 있으면 해당 정보를 우선 적용합니다(§11 [24]).
- `severity[].score`는 숫자 점수가 아니라 CVSS 벡터 문자열일 수 있습니다. 이 설계의 계산 지원 범위는 CVSS v3.0/3.1이며 FIRST의 해당 버전 수식으로 Base Score를 계산합니다. v2·v4 지원 여부는 구현 확인 또는 확장이 필요합니다.
- 지원 벡터가 없으면 출처가 명확한 `database_specific.severity`의 정성 등급을 보조적으로 사용할 수 있습니다. `MODERATE`는 `MEDIUM`으로 표시하되 출처를 기록하고 숫자 CVSS 점수로 임의 변환하지 않습니다.
- 사용 가능한 심각도가 없거나 벡터 계산에 실패하면 심각도 미확인으로 기록합니다. 취약점 건수로 대체하거나 낮은 심각도로 간주하지 않습니다.

**(c) 심각도·정보 누락·조회 상태 분리**

| 필드 | 값·의미 |
|---|---|
| `security.max_known_severity` | 확인된 일반 취약점의 최대 등급. 순서: `CRITICAL > HIGH > MEDIUM > LOW > NONE`. 확인 가능한 등급이 없으면 `null` |
| `security.unknown_severity_present` | 조회된 일반 취약점 중 심각도 미확인 항목이 하나라도 있으면 `true` |
| `security.query_status` | `COMPLETE`: 정해진 검사 범위의 조회 완료, `PARTIAL`: 일부 누락·실패, `FAILED`: 보안 조회 결과를 얻지 못함 |
| `security.vulnerability_count` | 성공한 조회에서 확인한 일반 취약점 수. 전부 실패하면 `null`. 점수에는 사용하지 않음 |

`UNKNOWN_SEVERITY`를 심각도 순서에 넣거나 `QUERY_FAILED`를 등급으로 사용하지 않습니다. 취약점이 없고 조회가 완료됐으면 `max_known_severity = "NONE"`, `vulnerability_count = 0`입니다. 취약점은 있지만 모든 심각도가 미확인이면 `max_known_severity = null`, `unknown_severity_present = true`입니다. 일부 실패 시 확인된 등급을 유지하되 전체 최대 심각도라고 단정하지 않습니다.

예: Medium 취약점과 심각도 미확인 취약점이 함께 조회된 경우:

```json
{
  "verdict": "PASS",
  "total_score": 1,
  "security": {
    "max_known_severity": "MEDIUM",
    "unknown_severity_present": true,
    "query_status": "COMPLETE",
    "vulnerability_count": 2
  }
}
```

일반 CVSS 결과는 슬롭스쿼팅 총점에 더하지 않습니다. 따라서 `PASS`와 `CRITICAL`이 동시에 표시될 수 있으며 이는 슬롭스쿼팅 신호가 낮지만 알려진 취약점은 심각하다는 뜻입니다. `PASS`는 설치 안전성 보증이 아닙니다.

**직접 의존성 수집 방식**

- 설치 전: PyPI `requires_dist`를 파싱하고 대상 환경에서 거짓인 환경 마커와 선택하지 않은 extra 전용 항목은 제외합니다. 조건을 만족하는 최신 안정 버전(사전 릴리즈 제외)을 검사 버전으로 추정합니다. 실제 설치 해결 결과와 같다고 보장하지 않습니다.
- 최대 30개. 제한으로 검사를 생략한 항목은 `incomplete`에 기록합니다.
- `--installed`: 원문 설계에 따라 `pipdeptree`로 실제 설치 버전을 확인하고, 사용 불가 시 메타데이터 방식으로 대체하되 추정임을 표시합니다.
- 전이 의존성은 검사하지 않습니다. `COMPLETE`는 이 문서에 정한 직접 의존성 범위 내의 완료를 뜻합니다.
- PyPI에 없는 의존성, 버전 해석 실패, OSV 조회 실패는 `signals`와 `incomplete`에 기록하며 보안 조회 상태를 `PARTIAL` 또는 `FAILED`로 표시합니다.

### 3.6 슬롭스쿼팅 총점과 임계값 (v0.7: OSV 제외, 최대 13점)

```
총점 = 등록기간(0~5) + 다운로드(1~5) + 이름유사(0~3)    (최대 13, OSV는 3.5의 별도 축)
총점 ≥ 7 → 부적합(FAIL)   /   4 ≤ 총점 ≤ 6 → 경고(WARN)   /   총점 ≤ 3 → 통과(PASS)
```

다운로드 항목의 최소점이 1점이므로 현재 점수표에서 실제 총점 범위는 1~13점입니다. 0~3점 PASS는 판정 구간 표기이며 0점은 현재 규칙으로 나오지 않습니다.

- 임계값 4점/7점은 v0.6까지 쓰던 6점/10점(당시 최대 18점, OSV 포함)을 **새 최대치(13점)에 비례 환산**한 값입니다(6×13/18≈4.3→4, 10×13/18≈7.2→7). 이는 "일단 숫자가 작아져서 생기는 간극을 메우는 임시 처리"일 뿐, **여전히 통계적 근거는 없는 플레이스홀더**입니다. 라벨 데이터셋으로 `experiments/tune.py` 를 돌려 근거 있는 값으로 교체할 예정입니다(§7 참고).

- 신규(≤7일) + 주간 다운로드 350 미만이면 5+5=10점으로 `FAIL`입니다. 여기에 이름 유사도 3점이 더해지면 13점입니다. 신규+이름 유사도 3점만으로도 다운로드 최소점 1점을 포함해 9점 이상입니다.

### 3.7 조회 실패·누락 처리

슬롭스쿼팅 총점이 `PASS` 수준이어도 필수 조회가 불완전하면 `UNKNOWN`으로 바꿉니다. OSV 실패도 MAL 여부를 확인하지 못하므로 포함합니다. **취약점 조회 성공 후 CVSS 정보만 없는 경우**는 조회 실패와 다르며 `unknown_severity_present`로 표시합니다.

| 누락·실패 항목 | 대체값·처리 |
|---|---|
| 등록일 이력 없음 | 등록일 5점, `incomplete` 기록 |
| 다운로드 통계 없음(404) | 다운로드 5점, 실제 0회와 구분하여 기록 |
| 다운로드 조회 오류 | 임시 3점, `incomplete` 기록 |
| 패키지 OSV 조회 실패 | 총점 영향 없음; 보안 조회 `PARTIAL` 또는 `FAILED`, `incomplete` 기록 |
| 직접 의존성 미존재·해석 실패·조회 실패·30개 제한 초과 | 보안 조회 불완전, `incomplete` 기록 |
| OSV 결과의 다음 페이지 미조회 | 보안 조회 불완전, `incomplete` 기록 |
| 검사 대상 PyPI 조회 실패 | 즉시 `UNKNOWN`; 점수 계산 중단 |

이미 `WARN`/`FAIL`이면 판정을 유지합니다. 적용되는 MAL 리포트가 있으면 다른 조회의 실패 여부와 무관하게 `FAIL`입니다.

## 4. 위험도 판정 기준 요약

### 4.1 통과 조건

아래가 **모두** 성립할 때 `PASS` 입니다.

- PyPI에 존재하고, 입력 형식이 올바르며

- OSV `MAL-*` 리포트가 없고

- 슬롭스쿼팅 총점이 3점 이하이며 (등록이 오래되었거나 사용량이 있거나 이름이 인기 패키지와 무관함)

- 필수 조회가 모두 완료되고 `incomplete`가 비어 있음

전형적인 통과 패턴: **오래되고(90일 초과) · 사용량이 많고(15,000회+) · 인기 패키지를 흉내 내지 않는** 패키지. (취약점 유무는 통과 여부와 **무관** — §4.3 참고)

### 4.2 위험·미존재·판정 불가 조건

| 구분 | 조건 | 해석 |
|---|---|---|
| **알려진 악성 보고** | 검사 버전에 적용되는 MAL 리포트 존재 | 악성 보고에 따른 차단. 슬롭스쿼팅 경로는 별도 확인 |
| **미존재** | PyPI에 패키지 또는 지정 버전 없음 | 환각·오타·삭제·다른 레지스트리 이용 등 원인을 구분해야 함 |
| **위험(부적합)** | 슬롭스쿼팅 총점 ≥ 7 (예: 신규 + 저다운로드, 신규 + 이름유사) | 여러 위험 신호가 겹침. 악성 확정 아님 |
| **주의(경고)** | 슬롭스쿼팅 총점 4~6 | 추가 확인이 필요한 초기 경고 기준 |
| **판정 불가** | 조회 실패로 확신 불가 | — (다시 시도 필요) |

전형적인 위험 패턴: **갓 등록되고 · 다운로드가 거의 없고 · 유명 패키지와 이름이 비슷한** 패키지.

### 4.3 보안 취약점(`security`)은 별도 축 — "정상/악성"과는 다른 질문

v0.7부터 OSV/CVSS 결과는 위 판정과 **섞이지 않습니다.** `security.max_known_severity` 는 "이 패키지를 설치하면 알려진 보안 문제가 있는가"를 알려주는 것이지, "이 패키지가 AI 환각/사칭인가"를 알려주는 게 아닙니다. 그래서 **통과(PASS) 판정을 받은 패키지도 `security.max_known_severity`가 CRITICAL일 수 있습니다** — 이건 모순이 아니라 "슬롭스쿼팅 위험 신호는 낮지만 취약점은 있다"는 서로 다른 사실을 동시에 보여주는 것입니다 (예시는 §5 참고).

## 5. 판정 예시 (설계 기준으로 계산한 가상 사례)

**슬롭스쿼팅 판정 (총점 최대 13, 통과 ≤3 · 경고 4~6 · 부적합 ≥7)**

표의 다운로드 수는 모두 최근 1주 값이며 이름 유사도 3점 행은 5자 이상인 다른 패키지명을 가정합니다.

| 상황 | 등록 | 다운로드 | 이름유사 | 총점 | 판정 |
|---|---|---|---|---|---|
| 성숙한 인기 패키지 (1000일, 500만회) | 0 | 1 | 0 | 1 | 통과 |
| 오래됐지만 사용량 적음 (1000일, 200회) | 0 | 5 | 0 | 5 | 경고 |
| 100일, 5,000회 | 0 | 3 | 0 | 3 | 통과 |
| 60일, 200회 | 2 | 5 | 0 | 7 | **부적합** |
| 20일, 5,000회 | 4 | 3 | 0 | 7 | **부적합** |
| 5일, 20,000회 (신규지만 폭발적 반응) | 5 | 1 | 0 | 6 | 경고 |
| 2일, 50회 (신규 + 저조, 전형적 슬롭스쿼팅 패턴) | 5 | 5 | 0 | 10 | **부적합** |
| 100일, 200회 + 이름유사(거리1) | 0 | 5 | 3 | 8 | **부적합** |
| 2일, 50회 + 이름유사(거리1) | 5 | 5 | 3 | 13 | **부적합** |
| 가상 사례 (등록 10일, 주간 10,500회) | 4 | 3 | 0 | 7 | **부적합** |
| 인기 패키지지만 `MAL-*` 리포트 존재 | — | — | — | (무관) | **부적합** |
| PyPI에 없는 이름 | — | — | — | — | 존재하지 않음 |

**별도 보안 축의 예시**

| 상황 | 슬롭스쿼팅 판정 | 최대 확인 등급 | 심각도 미확인 | 조회 상태 |
|---|---|---|---|---|
| 성숙한 인기 패키지, 일반 취약점 없음 | PASS | NONE | false | COMPLETE |
| 성숙한 인기 패키지, Low CVE 1건 | PASS | LOW | false | COMPLETE |
| 성숙한 인기 패키지, Critical CVE 1건 | PASS | CRITICAL | false | COMPLETE |
| 신규+이름 유사, 일반 취약점 없음 | FAIL | NONE | false | COMPLETE |
| Medium CVE와 심각도 미확인 CVE 존재 | 총점·MAL에 따라 판정 | MEDIUM | true | COMPLETE |
| 일반 취약점은 있지만 모든 심각도 미확인 | 총점·MAL에 따라 판정 | null | true | COMPLETE |
| 모든 OSV 조회 실패 | PASS 예정이면 UNKNOWN, 그 외 유지 | null | false | FAILED |
| 일부 OSV 실패, 나머지에서 High 확인 | PASS 예정이면 UNKNOWN, 그 외 유지 | HIGH | 조회된 항목 기준 | PARTIAL |

조회 실패 행의 `false`는 조회된 미확인 취약점이 없다는 뜻이며, 심각도가 알려져 있거나 안전하다는 뜻은 아닙니다. 모든 예시는 가정한 입력을 점수표에 대입한 결과이며 실제 패키지의 주간 통계나 코드 실행 결과로 제시하지 않습니다.

## 6. 기준값의 근거와 한계

### 6-1. 출처 유형과 적용 직접성

출처 유형과 우리 기준에 대한 직접성을 별도로 기록합니다. 공식 표준의 등급 정의를 논문보다 낮은 순위로 취급하거나, 논문의 간접 통계를 실무 자료로 분류하지 않습니다.

- **출처 유형:** 동료 심사 논문, 학위논문, 프리프린트, 공식 표준·문서, 실무 도구·연구자 분석, 사건 보도, 자체 설계.
- **적용 직접성:** 정의·기법을 직접 뒷받침하는지, 다른 생태계·시점·목적의 간접 참고인지, 우리 모델에서 별도 검증이 필요한지 구분합니다.
- 학위논문과 arXiv 게시 사실만으로 동료 심사 여부를 확정하지 않습니다. 뉴스는 사건의 보강 자료이며 임계값의 통계적 검증 자료가 아닙니다.

## 7. 성능 평가 방법

아래는 평가 설계입니다. 스크립트의 현재 지원 범위와 실험 완료 여부는 코드로 확인해야 합니다.

### 7.1 정답 라벨과 예측

- `label=1`: 출처로 확인된 비존재 환각 패키지명, 확인된 타이포스쿼팅, 또는 알려진 악성 패키지·버전.
- `label=0`: 평가 기준과 시점에 따라 선정한 정상 패키지·버전.
- `category`를 `hallucinated_nonexistent`, `typosquatting`, `confirmed_malicious`, `benign`으로 저장하고 중복 유형은 별도 태그로 보존합니다. MAL 또는 미존재만으로 슬롭스쿼팅 공격 경로를 정답 라벨로 부여하지 않습니다.
- AI 생성 맥락이 없는 단순 오타·삭제·누락 이름은 환각으로 자동 라벨링하지 않습니다. 출처 불명 항목은 주 평가에서 제외하고 개수를 공개합니다.
- `--positive warn`: WARN, FAIL, NOT_FOUND를 양성으로 간주합니다.
- `--positive fail`: FAIL, NOT_FOUND를 양성으로 간주합니다. MAL은 FAIL에 이미 포함되므로 별도로 중복 집계하지 않습니다.
- UNKNOWN·INVALID는 정상으로 집계하지 않습니다. 주 혼동행렬에서는 제외하되 판정 가능 비율과 제외 수를 함께 보고합니다.

위 이진 지표는 여러 유형을 합친 설치 전 위험 탐지 성능입니다. **슬롭스쿼팅만의 성능**으로 주장하려면 해당 공격 경로가 확인된 하위집합을 따로 평가해야 합니다.

### 7.2 혼동행렬과 지표

| 정답 | 예측 양성 | 예측 음성 |
|---|---|---|
| 평가 대상 위험 유형(label=1) | TP | FN |
| 정상(label=0) | FP | TN |

- Precision = TP / (TP+FP)
- Recall = TP / (TP+FN)
- F1 = 2·Precision·Recall / (Precision+Recall)
- FPR = FP / (FP+TN); 정상 1만 개당 오탐 수는 FPR×10,000입니다.
- 분모가 0인 지표는 미정의로 표시하며 0 또는 1로 임의 처리하지 않습니다.
- 전체와 유형별 지표, 판정 가능 비율을 함께 보고합니다.

### 7.3 점수·임계값 튜닝 설계

1. 층화 튜닝 70% / 최종 검증 30%로 분할하고 seed를 고정합니다. 최종 검증 세트로 기준을 선택하지 않습니다.
2. 동일 패키지의 여러 버전·이름 변형·공격 캠페인은 가능한 한 같은 그룹에 배치합니다. 캠페인 기준 분할과 시간 기반 분할도 별도 평가하며, 그룹 정보가 없으면 한계를 표시합니다.
3. 현재 점수표에서는 총점 임계값 1~13을 탐색합니다. 등록일·다운로드 경계값과 신호별 상대 가중치도 제한된 grid search로 비교합니다. 가중치 변경 시 최대 총점과 탐색 범위를 다시 계산합니다.
4. `warn_threshold`는 튜닝 세트에서 F1 최대 지점으로 선택합니다(동점이면 낮은 값). `fail_threshold`는 WARN보다 높으며 Precision ≥0.95를 만족하는 가장 낮은 값으로 탐색합니다. 양성 예측 수와 신뢰구간도 보고합니다.
5. 조건을 만족하는 FAIL 기준이 없으면 목표를 달성하지 못했다고 표시합니다. 운영용 임시 기준을 유지할 수 있지만 이를 검증된 95% Precision 기준으로 부르지 않습니다. WARN=최대 총점이면 유효한 더 높은 FAIL 임계값이 없다는 점도 명시합니다.
6. 선택한 점수·경계값·임계값을 고정한 뒤 최종 검증 세트로 평가합니다. MAL과 NOT_FOUND 예외를 포함한 전체 성능과 점수만의 성능을 따로 보고합니다.

### 7.4 최종 검증과 기저율 보정

- **전체 평가**와 **조회 시점에 존재하는 패키지만의 평가**를 나눕니다. 후자는 삭제된 악성 패키지를 NOT_FOUND로 쉽게 탐지하는 효과를 분리하기 위한 것입니다.
- π는 해당 평가에서 정의한 양성 유형의 실제 환경 비율입니다. **0.1%는 실측값이 아닌 가정값**이며 0.01% / 0.1% / 1%에서 민감도 분석을 합니다.

```text
기대 Precision = Recall × π / (Recall × π + FPR × (1 − π))
```

- 이 계산은 Recall과 FPR이 실제 환경에서도 유지된다는 가정에 기반합니다. 모집단·시점이 다르면 보정값도 달라질 수 있습니다.
- `reported_at`이 있으면 등록 후 경과 기간을 신고 시점 기준으로 계산할 수 있습니다. 다만 현재 다운로드·최신 버전·현재 OSV를 함께 사용하면 완전한 과거 시점 재현이 아닙니다. 각 신호의 수집 시점을 기록하고 과거 스냅샷 평가와 현재 상태 평가를 구분합니다.

## 8. 알려진 한계와 우회 가능성

**오탐(정상인데 위험으로 판정)이 날 수 있는 경우**

- 갓 등록된 정상 신규 패키지 (등록일 + 낮은 다운로드가 같은 신호)

- 인기 패키지와 우연히 이름이 가까운 정상 패키지 (예: `willow`↔`pillow`)

- 사용량이 적은 사내/틈새 패키지

**미탐(악성인데 통과)이 날 수 있는 경우**

- 공격자가 다운로드 수를 부풀리거나, 시간이 지나기를 기다려 "오래된 패키지"가 된 경우

- 오래된 정상 패키지에 **새 악성 버전**이 올라온 경우 (최초 등록일만 보므로 못 잡음. 단, OSV `MAL-*` 등록 시 잡힘)

- OSV에 아직 등록되지 않은 신규 악성 패키지

- 동형문자나 콤보스쿼팅 전용 탐지는 없음. `0`/`o`처럼 단순 치환은 편집거리로 탐지될 수 있지만, 전용 시각 유사성 분석이나 긴 접미사 조합을 모두 포괄하지 못함

**구조적 한계**

- 코드 내용을 분석하지 않음(정적/동적 분석 없음). 메타데이터 신호 기반의 **사전 경고 도구**.

- 현재 모델은 pypistats의 최근 1주 값만 사용함. 서비스가 제공하는 모든 통계가 최근 1주로 제한된다는 뜻은 아님. 과거 평가에는 당시 주간 스냅샷이 필요함.

- 전이 의존성은 미검사. OSV 첫 페이지만 처리하는 구현이라면 다음 페이지가 남았을 때 `incomplete`와 `PARTIAL`로 표시해야 함. 실제 구현의 페이지 처리 여부는 확인 필요.

- CVSS 벡터 해석은 v3.0/3.1만 지원(§3.5). v2·v4 벡터는 미지원이라 이 경우 `database_specific.severity`(있으면)로 대체하거나 "심각도 미확인"으로 처리됩니다.

- 인기 패키지 목록이 정적(175개)이라 범위가 좁음.

- **등록일 구간(7/30/90일)의 근거 자료(§3.2, §11 [9]~[14])는 대부분 "이미 존재하는 패키지에 새 버전이 게시된 경우"(공급망 탈취)를 다루며, "패키지 자체가 처음 등록되는" 슬롭스쿼팅 상황에 그대로 적용 가능한지는 별도로 검증되지 않았습니다. 두 상황 모두 "게시 후 얼마나 지났는가"라는 동일한 원리를 쓰지만, 적발까지 걸리는 기간의 분포가 다를 수 있습니다.**

- **다운로드 수 하한(350회)의 근거인 SpellBound 논문은 2020년 2월 PyPI 스냅샷을 사용했습니다(§3.3, §11 [7]). PyPI 규모와 봇/미러 트래픽 패턴이 그 사이 달라졌을 수 있어, 정확한 비율(93.3%, 15,000 등)은 최신 데이터로 재확인이 필요합니다.**

**`scan` 기능의 한계**

- 텍스트에서는 `pip install ...` 명령(줄 시작·코드 블록·인라인 코드·Dockerfile `RUN`)만 인식. 산문 속 문장은 무시.

- `import` 이름과 PyPI 이름이 다른 경우(`cv2`→`opencv-python`)가 많아 import 문 기반 추출은 하지 않음.

## 9. 발표용 요약 문장

1. “설치 전에 확인 가능한 메타데이터로 슬롭스쿼팅 위험도를 경고하는 도구입니다. PyPI 미존재는 환각 의심이며 악성 확정은 아닙니다.”
2. “등록일·주간 다운로드·이름 유사도 3개 신호를 최대 13점으로 합산하고, PASS ≤3 / WARN 4~6 / FAIL ≥7을 초기 기준으로 사용합니다.”
3. “알려진 일반 취약점은 CVSS 기반 별도 보안 축으로 표시하고, 검사 버전에 적용되는 MAL 리포트는 점수와 무관하게 FAIL로 처리합니다.”
4. “출처 유형과 적용 직접성을 구분합니다. 논문·공식 문서의 선례를 참고했지만 점수와 최종 임계값은 자체 휴리스틱이며 데이터셋으로 검증할 계획입니다.”
5. “오탐률, 위험 유형별 성능, 기저율 가정에 따른 기대 Precision을 함께 평가합니다.”
6. “통과 수준이라도 필수 조회가 불완전하면 UNKNOWN으로 표시하고, 심각도 미확인은 CVSS 등급과 구분합니다.”
